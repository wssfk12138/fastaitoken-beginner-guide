# 08. API Key 安全须知（3 条铁律防盗刷）

[⬅️ 上一章：常见报错排查](07-troubleshooting.md) · [🏠 返回首页](../README.md) · [➡️ 下一章：小白常见问题 FAQ](09-faq.md)

> [!TIP]
> **本章一句话看懂**：`sk-` 开头的 **API Key 就是你的免密支付卡**。谁拿到了这串字符，谁就能在自己的软件里直接花你账户里的钱。下面 **3 条防盗刷习惯** 能降低风险，仍需使用可信软件并定期检查用量。

---

## 一、🔒 小白防盗刷 3 条铁律

### 铁律 1：一个软件配一把专用钥匙（不要一把 Key 走天下）
在 [API 密钥页面](https://www.fastaitoken.com/keys) 创建密钥是完全免费的，你可以创建很多把。
- 给 Chatbox 建一把叫 `我的Chatbox`；
- 给 Codex 建一把叫 `电脑Codex`；
- 给浏览器翻译插件建一把叫 `沉浸式翻译`。
**好处**：在后台看账单时，哪把钥匙花了多少钱一清二楚；万一某个插件不安全或某台电脑不用了，直接把对应的那把钥匙停用/删掉就行，完全不影响其他软件正常使用！

### 铁律 2：创建钥匙时随手设上“小额度上限”
新建令牌时，不要图省事直接留着“无限额度”。
- 平时够用多少就设多少（比如先设 `$1`、`$5` 等值额度）；
- 快用完了再去后台点「编辑」往上加一点。
**好处**：就算你的钥匙不小心泄露了，或者某个自动化编程工具陷入了死循环疯狂发请求，额度限制有助于控制损失，但并发和结算延迟可能使实际扣费与阈值有差异；它不能替代密钥保护和账单检查。

### 铁律 3：绝不截图露 Key、绝不发群、绝不传上 GitHub
- 截图向网友或群友求助报错时，**先检查截图里有没有露出 `sk-` 开头的字符**，有的话必须用马赛克彻底涂黑；
- 不要把密钥存进公开的网盘文档、公开的 Notion 页面或发在聊天群里；
- 如果你用 Codex 写代码并上传到 GitHub，**绝对不要把填了真实密钥的配置文件（如 `.env` 或 `auth.json`）提交上去**；即使仓库暂时是私有的，也不要提交真实密钥。

## 二、如果你在写代码项目，钥匙应该存在哪？

如果你用 Codex 或自己写脚本开发项目，请记住这条黄金法则：**代码文件里只写“变量名”，真实密钥只放在本机不上传的文件里**。

1. **Codex 全局配置仍是敏感文件**：
   我们在 [第 05 章](05-openai-codex.md) 里把 `auth.json` 放在了 `C:\Users\你的用户名\.codex\auth.json`，它通常位于项目之外，可降低误提交风险，但本机恶意软件、共享账号或同步备份仍可能读取它；自定义 `CODEX_HOME` 时还要核对实际路径。**不要把 `auth.json` 或含 Key 的配置备份复制进项目或公开同步目录。**
2. **如果项目本身需要 `.env` 配置文件**：
   请一定在项目根目录的 `.gitignore` 文件里加上下面三行，让 Git 自动忽略真实密钥文件：
   ```gitignore
   .env
   .env.*
   !.env.example
   ```
   如果需要给别人看配置模板，只上传一个填了假占位符的 `.env.example`：
   ```text
   FASTAI_API_KEY=sk-your-key-here
   ```

---

### 还要保留的安全边界

- **不要把 Key 硬编码进公开网页的 JavaScript**：网页访问者可以从代码或网络请求中提取它，前端打包和混淆不能保密。
- **只填进可信客户端**：不要把 Key 交给来源不明的软件、脚本、浏览器扩展或所谓在线检测站。
- **优先用环境变量或可信本机配置**保存真实 Key，示例文件只放占位符；`.gitignore` 不会让已经被 Git 跟踪的秘密自动消失。
- **定期查账并处理共用设备**：离开公用电脑前清除本机 Key、退出账户；不再使用的设备或客户端应停用其专用 Key。

## 三、万一不小心把真实 API Key 发到了群里或传上了 GitHub，怎么办？

> [!CAUTION]
> **如果你发现自己刚刚在群里发了没打码的 Key 截图，或者把带 Key 的文件 `git push` 到了 GitHub（哪怕之后又删掉了文件重新提交了一次），旧的历史记录里依然能翻出那把 Key！**

请立刻按这 **3 步急救法** 处理（全程只需 1 分钟）：

1. **第一步（立刻止损）：去控制台直接删掉或停用那把泄露的旧 Key**
   打开 [FastAiToken API 密钥页面](https://www.fastaitoken.com/keys)，找到那把泄露的密钥，直接点击 **「删除」** 或 **「禁用」**。撤销能阻止后续使用；已经发出的请求或延迟入账的费用仍需核对。
2. **第二步（换新锁）：重新创建一把新 Key**
   点「添加令牌」建一把新的（记得设好分组和额度上限），把新 Key 换进你自己的软件里。
3. **第三步（核对账单）：看一眼使用记录**
   去「使用记录」查看是否有陌生调用；如有异常消费，保留时间、请求 ID 和脱敏日志并联系平台。必要时再清理仓库历史，但无论历史是否清理，旧 Key 都必须作废。

## 四、对话内容的隐私保护提醒

除了保护好 `API Key` 不被别人盗刷之外，平时跟 AI 聊天或写代码时，也请保护好你自己的内容隐私。无论使用哪家中转服务或第三方客户端，都请避免在提问中直接粘贴：

- 身份证号、银行卡号、支付密码、手机短信验证码；
- 服务器 SSH 私钥、云厂商（阿里云/腾讯云/AWS）的 AccessKey、生产数据库密码；
- 未经脱敏处理的真实客户名单、患者医疗记录或涉密合同原文；
- 公司严禁外传的内部未公开源码与商业机密；
- 没有获得上传授权的第三方内容。

正式业务使用前，应核对平台服务条款、隐私政策、记录范围和保存时间，并确认符合组织的数据处理要求。平台的“不留存”声明不能替代你自己的评估。

养成“敏感信息先脱敏（把真实姓名/密码替换成 `XXX`）再提问”的好习惯，既能充分利用 AI 提高效率，又能守住数据安全底线。
