# API Key 安全须知

[上一章：排错](07-troubleshooting.md) · [返回首页](../README.md) · [下一章：FAQ](09-faq.md)

API Key 同时是身份凭证和消费凭证。别人拿到它，可能使用你的余额，甚至让你难以判断费用来自哪里。

## 必须做到

- 每个设备或客户端使用不同的 Key，方便单独停用和追踪。
- 能设置额度、有效期或模型范围时，按实际需要限制。
- 只把 Key 填进可信客户端的密钥设置项。
- 定期查看使用记录，发现异常立即停用对应 Key。
- 离开公用电脑前删除 Key，并退出账户。

## 绝对不要做

- 不要把 Key 写进 README、教程、Issue 或聊天群。
- 不要把真实 Key 提交到 Git 仓库，即使仓库暂时是私有的。
- 不要在直播、截图或录屏中露出 Key。
- 不要把 Key 硬编码到公开网页的 JavaScript 中。
- 不要把 Key 交给来源不明的软件、脚本或浏览器扩展。

## 在代码项目中怎么保存

优先使用环境变量或本机配置文件：

```text
FASTAI_API_KEY=sk-your-key
```

如果项目使用 `.env`，把它加入 `.gitignore`：

```gitignore
.env
.env.*
!.env.example
```

公开的 `.env.example` 只写占位符：

```text
FASTAI_API_KEY=sk-your-key
```

Codex 的 `~/.codex/auth.json` 也属于敏感文件，不要复制进项目目录。

## 已经把 Key 推到 GitHub 怎么办

仅仅删除文件或新增一次提交不够，因为旧提交仍可能保留它。立即执行：

1. 在 FastAiToken 控制台停用或删除泄露的 Key。
2. 创建新 Key，并更新受影响的客户端。
3. 查看使用记录和余额是否异常。
4. 必要时清理 Git 历史；但无论是否清理，旧 Key 都必须作废。
5. 若发生异常消费，保留记录并联系平台支持。

不要等待“确认有人用过”再撤销。一旦公开，就应按已经泄露处理。

## 内容隐私也很重要

即使 API Key 保护得很好，请求内容仍会经过中转服务。不要发送：

- 身份证、银行卡、密码和验证码
- SSH 私钥、云服务密钥、数据库口令
- 未脱敏的客户资料和医疗信息
- 公司机密、未公开商业材料
- 没有授权上传的第三方内容

正式业务使用前，应阅读平台当前服务条款和隐私政策，并确认数据处理方式符合你的要求。
