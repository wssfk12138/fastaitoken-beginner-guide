# 07. 常见报错 10 秒速查与排查

[⬅️ 上一章：Chatbox 与其他客户端配置](06-client-config.md) · [🏠 返回首页](../README.md) · [➡️ 下一章：API Key 安全须知](08-security.md)

> [!TIP]
> **遇到红色报错先别慌，更不要急着反复充值或卸载重装软件！** 地址路径、模型 ID 和分组是常见检查项，也可能涉及余额、网络、限流或平台故障。先对照下面的表格缩小范围，再结合完整报错和日志判断。

---

## 一、🚨 报错代码 10 秒速查表（看到什么报错 → 怎么一键修好）

| 你在软件里看到的报错数字或提示 | 大白话翻译：到底哪里出问题了？ | 最快解决动作（按这个改就行） |
| --- | --- | --- |
| **`401`**<br>`invalid_api_key` / `Unauthorized` | **钥匙不对**。平台不认识你填的这串 API Key。 | 去控制台 [API 密钥页面](https://www.fastaitoken.com/keys) 重新点「复制」粘贴一次；检查密钥头尾是不是多带了空格、是不是删掉了开头的 `sk-`、或者该 Key 已被停用/过期。 |
| **`404`**<br>`model_not_found` / `当前分组无此模型` | **菜名点错了，或者去错了餐厅窗口**。模型 ID 写错了，或者你这把 Key 绑定的「分组」里没有这个模型。 | 1. 去控制台「可用渠道/模型广场」**直接点击复制准确的模型 ID**（注意大小写和连字符，如 `gpt-6.1-sol`，别手打展示名）；<br>2. 去 [API 密钥页面](https://www.fastaitoken.com/keys) 点「编辑」，确认这把 Key 的**「分组」**选在了支持该模型的分组上！ |
| **`404`**<br>日志里出现 `.../v1/v1/chat/completions` | **地址写重复了**。客户端已经自动帮你加了 `/v1`，你又手动填了一个 `/v1`。 | 把客户端里的 Base URL 从 `https://www.fastaitoken.com/v1` 改成 `https://www.fastaitoken.com`（确保最终请求里只有一个 `/v1`）。 |
| **`429`**<br>`insufficient_quota` / `额度不足` | **余额不够，或者这把钥匙达到了你设的限额**。 | 先看一眼账户总余额够不够；如果总余额充足，去 [API 密钥页面](https://www.fastaitoken.com/keys) 检查是不是这把 Key 自己设的「可用额度上限」用完了，点编辑调大即可。 |
| **`429`**<br>`rate_limit_exceeded` / `请求过于频繁` | **说话太快、太密了**（注意：同样是 `429`，这个**不是**没钱了，千万别盲目去充值！）。 | 停下正在同时运行的多个任务，等十几秒再试；如果用了沉浸式翻译或并发脚本，把软件里的「每秒最大请求数 / 并发数」调小。 |
| **`403`**<br>`Image generation is not enabled for this group` | **当前分组没开画图权限**，或者该分组不支持当前操作。 | 去控制台看哪个分组支持该图片/特殊模型，修改 API Key 的分组或新建一把对应分组的专用 Key，并先看清按次计费单价。 |
| **`400`**<br>`invalid_request_error` | **软件发出的请求格式不对**。 | 1. 把客户端里自己改过的温度（Temperature）、Max Tokens 等高级参数恢复默认；<br>2. 检查是不是把普通软件的 `/v1` 地址和 Codex 的 `responses` 协议混用了。 |
| **`500 / 502 / 503 / 504`**<br>`server_error` / `bad_gateway` | **通常涉及网关、上游或服务器处理失败**，仍需结合完整错误、网络和日志判断。 | 不要疯狂连点重试（避免重复扣费）；等 1~2 分钟后用一句短话再试，或者在控制台切换到同分组下其他可用模型。 |
| **Codex 启动后还是跳浏览器让我登录 OpenAI 官方账号** | **可能是配置未加载，也可能是认证或服务商选择问题。** | 先检查真实扩展名、实际配置目录（含 `CODEX_HOME`）、服务商选择和配置解析错误。已有文件先备份，再按 [第 05 章 B2](05-openai-codex.md) 针对性修正；B1 遇到已有配置会备份并停止。 |

## 二、遇到任何连不上的情况，按这 5 步顺序自检

如果报错文字不太明确（比如只提示“网络连接失败”或一直转圈没反应），请按顺序打勾检查这 5 件事：

1. **【查测试句】先把问题换成最短的一句话**：
   新建一个空白对话，只发 `请只回复：连接成功`。如果短句能秒回、长文却超时，可能与内容大小、处理时长或超时设置有关，再结合日志排查。
2. **【查分组与模型 ID】钥匙的分组和模型对得上吗？**：
   去控制台确认：你当前填的模型 ID 是不是从控制台复制出来的原样字符？你当前这把 API Key 的「分组」包不包含这个模型？
3. **【查地址】Base URL 有没有多写或少写 `/v1`？**：
   - 普通聊天软件（Chatbox / Cherry Studio）：目标是让最终请求发往 `https://www.fastaitoken.com/v1/chat/completions`；
   - OpenAI Codex (`config.toml`)：填 `base_url = "https://www.fastaitoken.com"` 且 `wire_api = "responses"`。
4. **【查网络与重试开关】关掉多余干扰**：
   如果你开了全局 VPN、特殊代理规则或拦截软件，导致国内直连被绕远甚至阻断，可以先暂停代理试一次；同时如果软件支持“失败自动重试”，先把重试次数调低或关掉，防止配置错误时连续刷请求。
5. **【查控制台日志】去后台看有没有收到请求**：
   打开 FastAiToken 控制台的「使用记录 / 日志」：
   - 如果后台**根本没有任何新记录**：可能是请求未到达、鉴权前被拦截，也可能是时间/筛选条件或记录延迟；先清除筛选并核对时间，再查客户端日志和地址；
   - 如果后台**有记录但显示失败**：表明平台记录到了相关请求，但仍可能有路径、模型、权限或参数问题；对照时间、请求 ID 和具体错误继续排查。

## 三、找客服或发帖求助时，怎么发信息又快又安全？

如果你按上面排查完还是解决不了，需要联系平台客服（具体联系方式见 [FastAiToken 简易使用文档底部技术支持](https://docs.fastaitoken.com/docs/easyuse) 或 [疑难杂症页](https://docs.fastaitoken.com/docs/help)），请这样准备信息：

- ✅ **应该提供的信息（能让客服一秒定位问题）**：
  1. 报错发生的大致时间；
  2. 你用的软件名字和版本（如 Chatbox、Cherry Studio 还是 Codex）；
  3. 你填写的**模型 ID** 和这把 Key 所在的**分组名称**；
  4. 报错弹窗里的**状态码（如 404、429）和完整英文/中文报错文字**；
  5. 脱敏后的 Base URL、请求端点，以及平台返回的请求 ID（如果有）；
  6. 如果截图，**先遮住 API Key 和 IP，检查是否含其他未经授权公开的内容**。本指南实拍图按账户所有者授权保留用户名、余额和用量，不代表他人的相同数据可直接公开。
- ❌ **绝对不能发出去的信息**：
  - **千万不要把未打码的完整 `sk-...` API Key、账户登录密码、付款记录原图直接发到公开的 QQ 群、微信群或 GitHub Issue 里！**
  - 如果不小心在截图里露出了完整 API Key，请不要犹豫，立刻去控制台把这把旧 Key 删掉，重新建一把新的（详见下一章 [安全须知](08-security.md)）。
